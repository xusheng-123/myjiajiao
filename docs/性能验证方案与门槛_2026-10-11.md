# 性能验证方案与门槛（2026-10-11 本轮，测试前固定）

> 本方案在执行任何压测之前写定并固定。验收门槛先于结果存在；结果不足时如实记录，不事后放宽。
> 本机合成数据与结论只描述这台工作站，不代表生产 SLA、加速倍数或全栈上线状态。

## 2. 数据规模（逐级扩大，全部合成，只进隔离库）

| 级别 | 检索条目（在售课程报价） | 教师数 | 说明 |
|---|---|---|---|
| L1 | 25,000 | 1,250 | 每教师 20 条在售条目 |
| L2 | 50,000 | 2,500 | 在 L1 基础上追加 |
| L3 | 100,000 | 5,000 | 本轮上限目标 |

分布设计（确定性伪随机，期望值可由 SQL 直接复算）：

- 科目：9 类基础科目 + 教师序号后缀（保证 ILIKE/相似匹配可控）；学段：小学/初中/高中。
- 价格：8,000–60,000 分均匀分布；审核状态：约 94% APPROVED / 3% PENDING / 3% REJECTED（仅 APPROVED 可见）；账户状态约 98% ACTIVE / 2% LOCKED（不可见）。
- 评价：每教师 0–8 条（评分 1–5），随附真实 booking 关联；可约档期：每教师 2–8 个未来 OPEN 槽。
- 每级灌入后执行 ANALYZE。

真实归属业务元数据（避免只测空接口；列表均为登录态按归属过滤）：

- 240 学生账户 + 60 家长账户 + ACTIVE 监护绑定；登录测试主账号（学生/家长/教师各≥1）复用项目既有验收密码。
- 客服工单约 3,000（学生/教师/家长归属分布 + 少量 booking 关联）、回复约 6,000、工单证据元数据约 1,200。
- 咨询会话约 300（师生真实对），每会话 20–80 条消息（合计约 1.5 万条），主测试会话 1 条 80+ 消息用于分页。
- 学习附件元数据约 600（学生归属 + 配额行）、咨询附件元数据约 120（消息关联）。

## 4. 并发、持续时间与冷启动

- **短时基线**：并发 8 → 16 → 32 逐级，每级 90 秒，级间静默 30 秒；每级吞吐/延迟独立记录。
- **持续负载**：32 并发持续 15 分钟（最高级别即 32；若本机资源不可承受，如实记录降级级别与停止原因，不虚报）。
- **规模曲线**：L1/L2/L3 每级在 8 并发下以相同五排序组合各测一轮，得到条目规模—延迟曲线。
- **冷启动**（如实标注范围）：① JVM/应用冷启动计时（进程启动 → health UP）；② 重启 PostgreSQL 容器（清 shared_buffers）+ 应用重启后的首轮访问（每接口 5 次）。**OS 文件缓存不清除**，故只称「应用 + 数据库缓冲冷启动（OS 文件缓存未清）」，不称完全冷缓存。

## 5. 指标

P50/P95/P99（nearest-rank）、吞吐 req/s、失败率、HTTP 状态分布；应用进程 CPU%/内存；PG 活跃连接数（pg_stat_activity 采样）；>1s 慢查询采样（pg_stat_activity 轮询 + 关键 SQL `EXPLAIN (ANALYZE, BUFFERS)`）；瓶颈定位记录执行计划/查询次数/资源指标。

## 6. 正确性校验（贯穿，不只统计 HTTP 200）

- **内容**：marker 切片 totalElements 与种子期望一致；price 排序页内单调；评分/评价数/档期字段与种子一致；匿名返回不含联系方式/资质文件 key。
- **分页**：相邻页键不重叠不遗漏；尾页大小正确；总数在负载期间稳定。
- **权限**：匿名检索 200；匿名业务接口 403；跨用户工单/消息/附件不可见（抽样断言他人记录不在结果）；ADMIN 调 course-options 403；无效排序 400；被 LOCKED 教师不出现在公开结果。

## 7. 停止条件（达到即停并如实记录，不放宽）

1. 任一阶段失败率 > 1%（预期内的权限 4xx 校验请求除外）。
2. P99 > 10 秒，或 5xx/503 持续出现。
3. 应用 OOM 或 PG 连接耗尽报错连续出现。
4. 本机可用内存 < 1.5GB。

## 8. 验收门槛（本机标准，测试前固定；非生产 SLA）

| 阶段 | 门槛 |
|---|---|
| 短时基线 @L3/32 并发 | 混合负载 P95 ≤ 800ms；失败率 0；正确性校验 100% 通过 |
| 持续 15 分钟 @32 并发 | 失败率 ≤ 0.5%；P95 ≤ 1000ms；末 3 分钟吞吐中位数较首 3 分钟下滑 ≤ 20%；JVM 内存与 PG 连接数稳定（无单调增长）；无重复 >2s 慢查询堆积 |

门槛不满足 → 以执行计划/查询次数/资源指标定位 → 只做有证据支持的修复（保持返回契约、公开权限、监护实时校验、幂等与审计）→ 同条件复测 → 记录优化前后对比。
