## 新机器本地运行

需要Java25、PostgreSQL、Node/npm（重建前端时）、Python3（验收工具时）。先创建独立新数据库并授予应用账户权限，不对主库运行测试。JAR首次启动创建V1–V22表。

以下是配置方式，**新机器部署尚未实际执行**。从解压根目录启动后端；占位值需在本地替换，不能提交密钥：

```powershell
$env:NURTURE_DB_URL='jdbc:postgresql://127.0.0.1:5432/<独立新数据库>'
$env:NURTURE_DB_USER='<数据库用户>'
$env:NURTURE_DB_PASSWORD='<数据库密码>'
$env:NURTURE_ADMIN_PHONE='<管理员手机号>'
$env:NURTURE_ADMIN_PASSWORD='<自行设置强密码>'
$env:NURTURE_JWT_SECRET='<独立长随机密钥>'
$env:NURTURE_PAYMENT_SANDBOX_SECRET='<独立长随机密钥>'
$env:NURTURE_STORAGE_DIR='<独立持久文件目录>'
$env:NURTURE_CORS_ALLOWED_ORIGINS='http://localhost:4200'
$env:NURTURE_PAYMENT_SANDBOX_ENABLED='false'
# Java25须在PATH内
java -jar .\backend\nurture-backend-1.0.0.jar --server.address=127.0.0.1 --server.port=8080
```

默认使用运营线下收款，真实资金须在外部核实后确认。演示沙箱可设true，模拟回调不是微信/支付宝真实支付；模拟充值也不证明资金到账。

前端运行方式：

1. 本地开发：另开终端到`source/frontend`，执行`npm.cmd ci`，再`npm.cmd start -- --host 127.0.0.1`。已有proxy.conf.json转发`/api`至8080。端口被占用时，在独立副本同时修改后端端口和代理，不能占用已有服务。
2. production静态目录：用支持SPA回退和`/api`反向代理的同源服务器提供`frontend-static/`，API指向独立后端。仅静态托管不能登录交易。跨域部署从源码设NURTURE_API_HOST后执行`npm.cmd run build:pages`，再配置允许来源/TLS；服务器域名操作见RUNBOOK，尚未验收。

后端重建：在`source/backend`用Java25运行`mvn -Pintegration -Dspring.datasource.url=jdbc:postgresql://127.0.0.1:5432/<独立IT库> verify`。IT配置在`src/test/resources/application-it.yml`，按本地账户覆盖连接配置。原机真实命令/日志见交接及报告。
