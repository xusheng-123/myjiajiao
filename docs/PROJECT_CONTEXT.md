# PROJECT_CONTEXT — 项目背景与需求（只记录仍然有效的约束）

> 引用方：`PROJECT_HANDOFF.md`。内容以真实需求与硬约束为主，不复述功能清单（见交接文档进度表）。

## 1. 项目定位

「润物细无声 / NURTURE」线上家教与学习服务平台。名字取自杜甫《春夜喜雨》，**产品逻辑 = 在合适的时候提供合适的支持，不喧哗但持续发生**。

从「线上家教交易平台」演进为「家教交易 + 学习过程管理 + 学习成长陪伴平台」：
找老师 → 匹配 → 预约 → 改期 → 家长绑定 → 下单 → 支付 → 课堂 → 课后任务 → 教师反馈 → 学习成长 → 家长周报 → 下一节课。

## 2. 四类角色 + Agent

- **学生**：找老师 / 预约 / 课程表 / 课前任务 / 进入课堂 / 学习成长 / 档案 / 答疑 / 收藏
- **家长**：监护绑定（ACTIVE 才能代付）/ 家庭钱包 / 消费对账 / 学习周报
- **教师**：资质认证 / 档期 / 审批 / 课堂准备（外部会议链接）/ 结课考勤 / 课后任务 / 课堂记录 / 答疑 / 结算
- **运营**：资质审核 / 退款两阶段仲裁 / 账户锁定 / 审计 / 线下收款确认
- **AI Agent**：服务账号（Token+Scope+审计+幂等），与人类走同一套 REST 契约——是入口不是独立系统

## 3. 用户明确提出的硬约束（违反即返工）

1. 技术栈锁定：Angular / Java 25 / Spring Boot / PostgreSQL。禁微服务化、Redis、Kafka、OpenSearch、Kubernetes、Ceph、自研 RTC、大模型 API（AI 上层能力均规划中）。
2. 不改品牌（润物细无声 / NURTURE）。用户2026-10-11已批准方向D黛绿暖金浅色，现以docs/ui-redesign-2026-10-11/design-system-d.md及品牌锁为准；原深色约束为历史，不把现有布局改回概念稿。
3. 不重写 Booking / Order / Payment / 认证 / 已稳定核心链路；新功能必须接入时才允许最小触碰。
4. 安全不妥协：「不要为了通过测试降低安全校验」；家长 A 不能操作 B 家庭学生；PostgreSQL 5432 不得暴露公网。
5. 不得擅自生产部署 / 修改生产数据库 / 接入真实支付（需用户决策与商户资质）。
6. 数据库只新增 Flyway 迁移，禁改历史迁移、禁手改表结构。
7. ADHD 友好与无障碍是内建标准（任务分块可跳过、状态不依赖颜色、尊重减少动效、键盘可达），不申请认证、不医疗化表述。
8. 无真实调研 / 经营数据时用「场景分析」表述，严禁编造百分比、营收、用户量、市占率、AI 能力、已上线状态。

## 4. 已确认的产品决策

- 支付模式 B「运营线下收款确认」为当前默认（已实现并并发实测）；A 沙箱=内测演示；C 真实渠道待商户资质。
- 课堂当前形态 = 外部会议链接登记 + 平台考勤留证；RTC SDK 待决策。
- AI 路线：本轮只建真实数据与规则化推荐（可解释理由，禁「AI 推荐指数」类虚构指标），AI 智能层为未来规划。
- 导航原则：不塞满；学习中心视觉 =「学习日记」而非「企业 BI Dashboard」。
