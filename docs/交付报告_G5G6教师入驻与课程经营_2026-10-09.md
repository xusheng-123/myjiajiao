## 1. G5 实现内容（教师工作台「资质认证」卡）

- **真实状态展示**：状态 pill 映射服务端四种真实状态 + 合成态（`○ 未提交`=NOT_SUBMITTED、`◔ 已提交`=SUBMITTED、`◷ 审核中`=UNDER_REVIEW、`✔ 已通过`=APPROVED、`↺ 需补充`=REJECTED）；已提交的显示服务端返回的提交时间。
- **上传入口**：未提交（NOT_SUBMITTED）或被驳回（REJECTED）时展示上传表单；审核中/已通过不展示（不提供多余入口）。
- **双必填文件**：身份证明（idDocument）+ 学历证明（degreeCert），与后端 `@RequestPart` 契约一一对应；两者都选中后提交按钮才解禁。
- **提交前文件清单**：显示文件名与人性化大小（B/KB/MB），可逐个移除（含重选同名文件的边界处理）。
- **前端校验（体验优化，如实标注）**：单文件 ≤20MB（与服务端 multipart 硬限制一致，超限即时拦截并提示）；界面文案明确「平台当前不限文件格式……最终以服务端校验为准」——**未虚构「只允许 PDF」等不存在的白名单**。
- **防重复提交**：busy 门控（按钮禁用 + 文案变化），multipart POST 携带幂等键（全局过滤器要求）。
- **服务端实际状态**：提交成功后直接渲染服务端返回的 VerificationStatusView，不在前端臆造状态。
- **审核中/驳回状态**：驳回态显式展示服务端真实审核意见（`审核意见：{decisionNote}` 独立区块）+ 服务端 guidance 文案；**后端有意见才显示，无意见不虚构**。
- **重新提交**：驳回后表单重现，重新提交=新建案例（既有语义），新案例走 SUBMITTED。
- **刷新恢复**：页面每次加载从 `GET /verification/me/status` 拉取真实状态；状态读取失败时有降级提示并保留上传入口。
- **错误提示**：服务端 detail 字段优先展示，无 detail 时给通用可行动文案。
- **安全边界保持**：材料无查看/下载端点（教师与运营均不可在线预览）；不暴露存储路径/内部键/绝对路径；上传走认证 Cookie，无公开接口。

## 2. G6 实现内容（教师工作台「课程与定价」卡，新增卡片）

- **课程列表**：科目 / 学段 / 价格（元/小时，分转元展示）/ 在售 pill（按服务端 active 字段如实展示）；数据来自 `GET /teacher/me/subjects`（服务端仅返回在售条目）。空态引导、加载态、读取失败态齐备。
- **新增条目**：科目 + 学段 + 定价（元/小时）表单，`POST /subjects`；前端校验必填与「正数、最多两位小数」；**D9 幂等如实提示**——同科目+学段重复添加时服务端返回既有条目，界面明确提示「已有在售条目（当前 ¥X/小时），未重复创建；如需改价请用『调价』」，不谎称新建。
- **调价**：行内「调价」面板，展示原价与新价输入（预填现价）；确认后 `PUT /subjects/{id}/pricing`；面板标注「调整后仅影响之后的新订单，已生成订单金额不变」；保存后用**服务端返回价**刷新列表（不从前端臆造）；非法价格被服务端拒绝时透出 detail（「课时定价必须为正数（单位：分）」）。
- **下架**：行内「下架」按钮 → **二次确认面板**；确认后 `DELETE /subjects/{id}`；文案如实为「下架（停止销售）」：说明学生将无法检索/预约、已生成订单不受影响、**下架不是删除记录、平台当前不提供自助重新上架（如需恢复请联系运营）**——因服务端无重新上架端点，**未添加重新上架入口**，未虚构状态流转。
- **无中间态价格**：前端不自行计算订单金额；元→分换算仅用于提交表单参数（两位小数以内，整数分），订单最终金额一律由服务端定价快照决定。

## 5. 文件类型 / 大小 / 授权规则（当前真实状态，非设计目标）

- **类型**：服务端**不限制**文件类型（`FileStorageService.store()` 仅校验非空；`LocalFileStorageAdapter` 不做类型白名单）。前端不虚构限制，如实提示「不限文件格式，PDF/JPG/PNG 等常见格式均可，以服务端校验为准」。**未验证**任意畸形文件的服务端行为（属服务端既有行为，本轮未改也未逐一探测）。
- **大小**：服务端唯一硬限制为 Spring multipart `max-file-size: 20MB`（application.yml，本轮未改）。前端同步校验 20MB。注意：两个文件同时较大时还受 multipart 请求整体上限约束（Spring 默认 10MB 请求级限制，配置未显式设置）——**这是当前真实约束，未做修改**；单个文件 ≤10MB 的双文件提交不受影响（走查即此场景）。如需放宽需改 application.yml（本轮范围外，未动）。
- **授权**：`POST/GET /verification/*` 类级 `@PreAuthorize`（TEACHER/ADMIN/teacher:write scope）；材料存储键为 UUID，无按 ID 越权读取面（本就没有读取端点）；`/teacher/me/subjects` 系列全部经 `ownedOffering` 对象级授权（非属主 403，E2E §8.6 断言）。**本轮未新增任何公开访问接口，未让任何教师能读取他人材料。**
- **隔离**：资质文件写入本地卷 `backend/data/files/`（已在 .gitignore），**未写入 Git/日志/测试报告**；E2E 用内存构造的伪 PDF 字节流，非真实证件。

## 6. 教师资质流程（当前实际，与界面一致）

1. 注册导师（姓名/手机号/密码/院校/学历）→ 登录进入工作台。
2. 「资质认证」卡显示「○ 未提交」+ 上传表单（新教师）。
3. 选择两份材料 → 清单确认 → 提交 → 服务端创建案例（SUBMITTED），界面即时反映 + 服务端提交时间。
4. 运营在后台「教师资质审核流转」批准或驳回（带 note）。
5. 驳回 → 教师端「↺ 需补充」+ 真实审核意见 + 重新提交表单；重新提交=新案例（旧案例历史保留）。
6. 通过 → 「✔ 已通过」，教师可发布档期；此时才会出现在学生「找老师」检索结果中（matching `isApproved` 门控，既有行为，本轮未动）。
7. 全程未新增任何审核状态；UNDER_REVIEW 由运营端流转产生（与界面文案一致）。

## 7. 教师定价管理流程（当前实际）

1. 「课程与定价」卡加载在售条目（仅 active）。
2. 新增：科目+学段+定价 → D9 幂等（同科目+学段唯一），重复添加返回既有条目并如实提示。
3. 调价：原价确认 → 新价校验（>0 分）→ 服务端更新 → 列表以服务端返回价刷新。
4. 下架：二次确认 → DELETE → 服务端 `active=false`（停止销售）→ 列表刷新后条目消失；检索立即不可见；**无重新上架入口**（服务端无该能力，界面如实说明「请联系运营」）。
5. 下架后该科目新订单由服务端兜底默认价 ¥300/小时（`DEFAULT_LESSON_PRICE_CENTS=30000`，既有行为）——E2E §8.6 已断言此兜底语义，界面未对兜底价做任何承诺或掩饰。

## 8. 价格快照保障（验证链）

- 下单金额在 `OrderApplicationService.createForCaller` 按教师**当时在售**条目价快照进订单（既有逻辑，未动）。
- **E2E §8.6 实测**：调价至 18000 分 → 新订单金额=18000 ✓ → 再调至 25000 → 已生成订单详情**仍为 18000** ✓（历史快照不可变）。
- 前端仅传递表单参数与渲染服务端返回金额；§16 已有「伪造金额被忽略（以订单为准）」断言持续覆盖。
- 未修改订单状态机、结算规则，未做任何历史数据迁移。
