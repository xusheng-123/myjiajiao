## 一、结论速览

对后端 **30 个 Controller、约 150 个 REST 端点** 与前端全部 Angular 组件的 HTTP 调用做了逐条比对，
并用四个真实角色（学生/家长/教师/运营）在 `http://localhost:4200` 走查确认。结论：

- **15 项功能后端完整可用、前端完全没有入口**（其中 4 项卡在交易履约闭环上，优先级最高）；
- **6 项属于重复/旧入口**（另一条路径已有 UI），建议标注下线候选，**不必补 UI**；
- **2 项面向 AI Agent 的集成端点**无 UI（可按需决定是否做管理界面）;
- 顺带发现 **7 个前端死常量**（其中 3 个指向后端根本不存在的路由），建议清理。

| 分类 | 数量 | 代表功能 |
|---|---|---|
| A. 交易履约闭环缺口 | 4 | 取消预约、开始/完成课程 |
| B. 学习成长缺口 | 6 | 学习画像、课堂记录、我的学生 |
| C. 评价缺口 | 2 | 教师公开评价列表、收到的评价 |
| D. 运营后台缺口 | 2 | 平台参数配置、登录限流解锁 |
| E. AI/集成（可选 UI） | 2 | Agent API Token、MCP 工具目录 |
| F. 重复/旧入口（勿补 UI） | 6 | 私有推荐、旧审批入口等 |
| G. 前端死常量 | 7 | 指向不存在路由的常量 |

## 三、A 类：交易履约闭环缺口（P0，建议最先补）

### A1. 取消预约（两阶段取消）—— 全站无任何「取消预约」按钮
- 端点：`POST /api/v1/booking/bookings/{id}:cancel/preview` → `POST /api/v1/booking/bookings/{id}:cancel/execute`
- 能力：先预览级联影响（订单/结算/名额），返回 10 分钟有效 confirmationToken，再携带令牌原子取消。
- 现状：`endpoints.ts` 里 `API.booking.cancelPreview/cancelExecute` 已定义但**从未被任何组件调用**；学生/家长/教师工作台均无按钮（浏览器已核实）。目前用户无法从网页取消课程，只能改期。
- 建议落点：学生/家长工作台课程卡 + 教师工作台今日课程卡，加「取消预约」→ 弹窗展示级联影响预览 → 二次确认执行。

### A2. 开始上课 / 完成课程 —— 预约状态机网页上走不完
- 端点：`POST /api/v1/booking/bookings/{id}:start`、`POST /api/v1/booking/bookings/{id}:complete`
- 能力：REQUESTED→CONFIRMED→**IN_PROGRESS→COMPLETED**；完成后才解锁双向评价与课堂记录。
- 现状：后端全库检索确认这两个方法**只被该 HTTP 端点调用**；教师「结束课堂」只结束课堂会话实体（`ClassroomApplicationService.endSession` 不改预约状态）。即 CONFIRMED 之后的两个状态网页无法到达 → 学生「评价」入口（lesson-history 只列 COMPLETED）对纯网页用户永远是空的。
- 建议落点：教师工作台今日课程卡「开始上课」；下课后「完成课程」（可并入现有"课堂准备"弹窗，与 endSession/考勤串成一个流程）。

### A3. 我的预约列表 / 预约详情 —— 学生侧没有预约总览
- 端点：`GET /api/v1/booking/me/bookings`（学生分页列表）、`GET /api/v1/booking/bookings/{id}`（详情）
- 现状：前端 0 调用。学生只能看到 focus-overview 里**下一节**迫近课程，没有历史/全部预约列表页（教师侧有 booking-requests 队列，学生侧没有对称页面）。
- 建议落点：学生工作台新增「我的预约」卡（分页列表 + 状态筛选），顺便承载 A1/A2 的按钮。

### A4. 导师审批重复入口（勿补 UI，见 F 类）
- `POST /api/v1/booking/booking-requests/{id}:decide` 与教师已在用的 `/teacher/me/booking-requests/{id}:decide` 功能重复，前端已接后者。

## 九、G 类：前端死常量清理（反向发现，防误导后人）

`frontend/src/app/core/api/endpoints.ts` 中以下常量**无任何组件引用**，其中带 ⚠ 的指向后端**不存在**的路由，若未来有人误用会 404：

| 常量 | 指向 | 状态 |
|---|---|---|
| `API.parent.childOverview` ⚠ | `/parent/me/children/{id}/overview` | 后端无此路由 |
| `API.parent.walletTransactions` ⚠ | `/parent/me/wallet/transactions` | 后端无此路由 |
| `API.parent.lessonProgress` ⚠ | `/parent/me/lesson-progress` | 后端无此路由 |
| `API.parent.reviews` ⚠ | `/parent/me/reviews` | 后端无此路由 |
| `API.student.preparationTasks` ⚠ | `/student/me/lessons/{lessonId}/preparation-tasks` | 后端无此路由（真实路由无 lessons 前缀） |
| `API.student.completeTask` | `/student/me/preparation-tasks/{id}:complete` | 路由存在但前端实际用 classroom 版 |
| `API.student.profile` | `/student/me/profile` | 路由存在但无 UI（见 B2） |
| 其余 | `API.learning.tasks / learning.profile / teacherTasks / createRecord / myRecords / myStudents / studentArchive / teacherQuestions / closeQuestion / matching.recommend / booking.cancelPreview / booking.cancelExecute` | 无调用（多数对应本报告 B/C/A 类缺口，补 UI 时正好启用） |

> 提示：`cancelPreview/cancelExecute`、`myStudents`、`closeQuestion` 等"死常量"正是 A/B/C 类缺口的直接证据——补 UI 时前端契约常量已备好。
