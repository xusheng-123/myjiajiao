## 一、既有缺口补齐（阶段一：纯前端，复用现有 API）

### G1. 运营「确认线下收款」入口
- **问题**：支付模式 B 的唯一操作入口缺失，试运营资金闭环走不通。
- **前端改动**：admin-dashboard 新增「订单与收款」卡：待支付订单列表 + 「确认已收到款项」按钮（两段确认）。
- **后端改动**：无（`POST admin/orders/{id}:confirm-offline-payment` 已实测）。
- **验收**：E2E 新链路——家长下单 → 运营界面确认 → 订单 PAID → 教师结算 +1 → 双方通知；重复确认显示幂等提示。
- **难度**：低 ｜ 风险：低（幂等已实测兜底）
- ✅ **已实施（2026-10-09）**：与规划一处偏差——后端实际缺只读列表端点，已补 `GET /admin/orders/pending-payment`（size≤50）；UI 走查另抓出 ngOnInit 漏调 `loadPendingOrders()` 的断点并修复。E2E +3，浏览器实测全链路（列表→二次确认→PAID→移出列表）通过。

### G2. 家长端「学习周报」入口

- **难度**：低 ｜ 风险：低

### G5. 教师「资质上传」入口 ✅ 已完成（2026-10-09）
- **问题**：新教师无法自助完成信任准入（当前靠测试预置账号）。

## 二、新增功能评估（阶段二/三候选）

### A. 个性化学习计划中心
- **解决问题**：学习目标散落在画像三个文本字段，无里程碑、无课程/任务关联进度。
- **现状证据**：`LearningProfile(goal/stage/targetSubjects)`（V9）；任务与课堂记录可关联进度；无计划表。
- **目标用户**：学生（设定/查看）、教师（调整/点评）。
- **方案（v1 规则化）**：新增 `learning_plans`（学生维度目标+科目）+ `plan_milestones`（标题/目标日期/状态/关联科目）；进度 = 里程碑完成数 + 关联任务完成率 + 已完成课程数（聚合既有数据，**不造新指标**）；教师可在授课关系内调整。
- **前端**：学生成长中心新增「我的计划」卡；教师端学生档案页加「调整计划」。
- **迁移**：后续未占用版本（原V11预案已被红冲占用，当前最新V12；两表）。｜ **依赖**：learning 既有结构。｜ **权限**：学生本人 / 授课教师（复用 requireTeachingRelation）。
- **难度**：中 ｜ **风险**：与既有画像字段职责重叠（方案：计划管「往前看」，档案管「往回看」，接口分开）。
- **验收**：设目标→教师加里程碑→学生完成关联任务→进度数字真实变化；无关教师 403。
- **优先级**：阶段二 ①（学习闭环的「往前看」半环，价值最直接）。

### B. 错题本与薄弱知识点
- **解决问题**：「存在问题」「下节建议」只有教师文本，学生无法自主积累错题、无法驱动针对性任务。
- **现状证据**：LessonRecord.problems；LearningTask 可按 booking 布置；无错题实体。
- **方案（v1 文本+科目标签）**：新增 `mistake_notes`（学生/科目/题目描述/错误原因/知识点标签/掌握状态 UNMASTERED→REVIEWING→MASTERED/复习时间）；学生 CRUD 本人；教师可在授课关系内查看并「一键转为课后任务」（复用 createTask，描述预填错题）。
- **前端**：学生端「错题本」页 + 教师端学生档案页「薄弱点」Tab。
- **迁移**：V12（一表）。｜ **依赖**：learning 任务。｜ **权限**：学生本人 / 授课教师只读。
- **难度**：中 ｜ **风险**：条目质量依赖录入习惯（用「教师可代录」缓解）。
- **验收**：录入→标记复习→转任务→完成→掌握状态流转；跨学生 403。
- **优先级**：阶段二 ②（与任务体系强协同）。

### C. 教学资料库与作业附件
- **解决问题**：任务/答疑目前纯文本；课件资料无沉淀。
- **现状证据**：`FileStorageService.store/load` 接口 + LocalFileStorageAdapter（base-dir 可配）已就绪；verification 已有 multipart 先例。
- **方案（v1）**：新增 `learning_files`（category: TASK_SUBMIT/MATERIAL/ANSWER/RECORD，storage_key，归属人，关联 booking/task/question，原始文件名/类型/大小）；下载走授权检查端点（参与方/归属人）；限制：白名单类型（pdf/images/office）、单文件 ≤20MB（沿用 multipart 配置）；删除=逻辑下架。**不重复建文件系统**。
- **前端**：任务提交/答疑表单加附件；教师端「资料库」列表卡。
- **迁移**：V13（一表）。｜ **依赖**：FileStorageService、learning 各实体。｜ **权限**：存储 key 不外泄，全部经授权下载端点流式返回。
- **难度**：中-高 ｜ **风险**：路径安全（adapter 已 normalize；仍需端到端授权用例）；存储增长（记录大小，暂不配额）。
- **验收**：上传→授权方下载一致→无关方 403；非白名单类型拒绝。
- **优先级**：阶段二 ③（B/A 的体验放大器，可紧随其后）。

### D. 阶段测评与学习效果报告
- **解决问题**：学习效果无阶段性客观锚点。
- **现状证据**：无测评实体；报告数据源（课程/任务/记录）已聚合于 archiveOf/weeklyReport。
- **方案（v1 客观题+人工批阅）**：`assessments`（教师创建，关联科目/范围）+ `assessment_items`（题干/选项/答案，教师录入）+ `assessment_attempts`（学生作答 JSON + 得分 + 教师批注）；报告 = 测评得分趋势 + 任务完成率 + 课堂记录要点（全部真实数据），页面明示「阶段性小结，非全面能力诊断」。
- **难度**：高（三表+批阅流+报告聚合）｜ **风险**：范围蔓延成题库系统（v1 限 20 题内小测）；「报告」被误读为权威诊断（固定文案声明）。
- **验收**：创建→作答→批阅→报告数字与作答一致；学生仅见自己作答。
- **优先级**：阶段三（依赖 A/B 数据沉淀）。

### E. 智能可约时间匹配与教师对比
- **解决问题**：家长/学生常按「什么时候有空」选老师；多名候选难并列比较。
- **现状证据**：`nextOpenSlotAt` 已在检索结果；收藏列表已实现；`openSlotViewsOf(teacherAccountId)` 可展开档期；对比无实现。
- **方案（v1）**：①检索响应已含时间——前端加「最早可约」筛选（纯前端过滤）；②教师卡/收藏页加「加入对比」，最多 3 名，并排展示价格/评分/风格/经验/最近可约（全部现有字段）；③「查看档期」抽屉拉真实 open-slots（点过去即可预约，杜绝展示失效时段）。
- **难度**：低-中 ｜ **风险**：档期时效（展示即拉取 + 点击直达预约，规避缓存失效）。
- **验收**：对比列 ≤3 且字段真实；从对比/抽屉可一键进入预约；筛选结果与 open-slots 一致。
- **优先级**：阶段三（可与 D 并行；也可提前到阶段一末尾——纯前端成本低，见实施顺序说明）。

### F. AI 学习助手
- **解决问题**：计划生成/错题解释/复习建议的效率。
- **现状证据**：无任何 AI 代码（有意为之）；Agent 五要素已就绪；学习数据（任务/记录/错题）在 A–B 落地后才有质量。
- **前置条件清单**：①用户明确授权与配置（密钥经 env，禁入库）；②数据保护（仅提交脱敏学习内容，可一键关闭）；③失败降级（模型不可用时显示静态建议）；④准确性（AI 输出一律标注「AI 生成，需教师/学生确认」，不进入成绩/评级）；⑤教师复核机制（AI 建议 → 教师确认才进档案）；⑥成本上限。
- **难度**：高 ｜ **风险**：数据外送、幻觉、成本失控。
- **优先级**：阶段四（明确低于一切流程补全；在 A+B+C 数据可靠后启动试点，仅接「错题解释/复习建议」两个窄场景）。

## 三、推荐实施顺序与理由

```
阶段一（先行）：G9 测试打底 → G1/G2/G4/G8 低风险入口 → G7 资金闭环可见 → G3/G5/G6/G10
阶段二：A 学习计划 → B 错题本 → C 资料库附件
阶段三：D 阶段测评 ｜ E 对比与时间匹配（可视工作量与阶段一末并行）
阶段四：F AI 助手试点（窄场景）
```

**为什么这个顺序**：
1. 阶段一全是**复用已实测 API 的前端工作**——用户价值立现、风险最低、且直接兑现「后端能力 → 可用功能」的欠账；G9 先行保证此后每个入口都有回归网。
2. 阶段二三项共享 learning 模块与存储基建，且互相喂数据（错题→任务→档案→计划），一次把「学习管理」做实——这是与同类产品的差异化主线。
3. 阶段三依赖前两阶段的数据密度（测评报告/对比才有内容），且 D 复杂度最高，不宜早做。
4. F 严格垫底：没有真实学习数据，AI 只能产幻觉；且需用户对成本/数据保护单独授权。
